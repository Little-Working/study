# 预先确定的协议：2026-09-24 低中并发运行时测试

- 六框架使用上次 lockfile 和同一个 Node 24.21.0 镜像，production 构建；本次不升级依赖。
- HTML 为 Hello World、约 800 KB、约 1.5 MB。真实 HTTP 后端分别传输约 41 B、320,000 B、600,000 B JSON，模拟 50/200/500 ms 定时等待。
- 并发 1/8，HTTP/1.1 keep-alive、闭环固定并发，不追求峰值吞吐。
- 108 个框架/页面/延迟/并发组合，每组合两次 20 秒窗口，共 216 个正式窗口。
- 每框架每种页面每轮独立进程；10 秒页负载预热，10 秒空闲基线；每组合另有 3 秒预热。第二轮反转框架/页面顺序，组合顺序按固定种子随机。
- 正式测量前每框架执行 lean/off/off/lean 四个独立进程的监控开销对照，每窗预热 10 秒、测量 15 秒（大页，50 ms，C8）。不按对照结果给指标乘修正系数。
- 应用 2 vCPU/1536 MiB/V8 old space1024 MiB、后端2vCPU、客户端4vCPU，VM CPU集合不重叠。客户端最多2workers，C1用1worker。串行运行框架，不在测量期间构建或制图。
- ETag 和应用压缩均关闭；主动请求 gzip/br 并用运行时哨兵验收。SvelteKit 移除产物中 HTML ETag 的 hash 调用，有补丁散列。静态资源构建哈希不属于动态请求计算。
- 相同 Event Loop 10 ms 原生直方图，记录样本数、p50/p75/p90/p95/p99/max；数值包含采样间隔，不等于纯阻塞时长。
- GC observer 遍历每批全部事件，预分配固定数组记录开始时间、时长、kind、flags；记录上限65536，溢出即判失败。按 minor/major/incremental/weakcb 和全类型分别计算最近秩分位数。没有事件时显示未观测到/null；不足100个事件的p99标为稀疏样本。
- 仅自检进程强制 GC，正式/开销窗口不使用显式 GC、不改GC调度、不抓CPU profile。
- 完整响应结束后先冻结应用/后端测量边界，再排序和序列化统计；GC 按开始时间归属并排除测量窗口以外的事件。
- 1 Hz采样rss/heap/external/arrayBuffers；逐请求不加监测；客户端正式窗口只检查状态、长度和头部，完整内容校验在独立验收阶段。
- 跨轮 EL 分位数展示两窗指标中位数及范围，不伪装成合并分位数；最大值取两窗最大。GC 可从原始事件合并计算，并单列分类型样本数。CPU/内存/RPS/HTTP延迟是辅助指标。
- 保存所有有效/异常窗口，不自动删除慢窗口。说明自然GC的有限观测，不把没观测到major解释为没有major风险。
- 结束后清理本轮标签的容器、网络、数据卷及本地临时构建数据，保留复现源码、锁文件、指标和报告。

实际镜像 API 核对补充：本 Node 版本另暴露 minor_mark_sweep（kind=2）。监测器原始记录保留所有 kind，包括未命名类型；离线报告依据实际常量将 kind=2 单独列出，不丢弃或改动原始事件。
